ATLAS Jetson quick commands
===========================

Documentation refreshed: 2026-10-11. This is not a new hardware validation.
Maintained branch: main. Historical snapshots are not deployment sources.

Existing installed runtime:
  /home/super-alex/atlas/ATLAS_School_Pilot_v1_integrated
Existing Python environment:
  /home/super-alex/atlas/venvs/atlas-school-pilot
User service:
  atlas.service

Run as super-alex on the Jetson:
  systemctl --user status atlas.service --no-pager
  systemctl --user start atlas.service
  systemctl --user stop atlas.service
  systemctl --user restart atlas.service
  systemctl --user is-enabled atlas.service

Start/stop/restart interrupts the experience; coordinate with the operator.
Do not start another ATLAS copy when the service already owns port 8765.

Public health:
  curl --fail http://127.0.0.1:8765/health
Admin dashboard:
  http://127.0.0.1:8765/admin
Visitor dashboard:
  http://127.0.0.1:8765/

Use the authenticated admin dashboard for status and camera preview.
/status and /camera/frame.jpg require admin authentication. Do not copy
tokens into this document or save visitor frames for troubleshooting.

Read-only preflight:
  cd /home/super-alex/atlas/ATLAS_School_Pilot_v1_integrated
  source /home/super-alex/atlas/venvs/atlas-school-pilot/bin/activate
  ./scripts/preflight_device.sh
  python -m pip check

Networking (addresses can change):
  hostname -I
  nmcli -f DEVICE,TYPE,STATE,CONNECTION device status
  nmcli -f NAME,TYPE connection show --active
SSH from another device on a permitted network:
  ssh super-alex@super.local

The hostname requires mDNS and network peer access. Otherwise use the
current IP from hostname -I, not a historical home address. School networks
may block peer traffic even after authentication. Read
atlas/docs/SCHOOL_WIFI_SETUP.md for school/hotspot fallback limitations.

- Do not rename the installed runtime during repository cleanup.
- Never publish API keys, Wi-Fi passwords, private keys, admin tokens,
  visitor logs, recordings, or databases.
- Mock tests passing does not prove live camera/audio/network behavior.
- Keep the October 4 deployment and pending physical checks explicitly dated.
